## Why

Martin owns and directs the **dnd-rsf2026** project — a Sanity + Next.js landing-page
generator for D-D The Aquarium Solution — but much of it was built at high speed by
agents. The mission is to **truly understand the system he owns**: what Sanity is as a
concept, how the page-builder architecture works, and why it was built this way — well
enough to:

1. explain it confidently to the client and to editors,
2. make schema/content decisions himself (new blocks, new products, translations),
3. debug and extend the codebase without re-learning it each time.

## Success looks like

- Can explain "structured content vs. pages" in one minute, unprompted.
- Can add a new block end-to-end (schema → component → demo → seed) without notes.
- Can predict what a GROQ projection returns before running it.
- Knows which of the two i18n strategies applies to which document type, and why.

## Grounding

All lessons use **this repository** as the example corpus — never foo/bar examples.
Reference docs live beside real files: `docs/SCHEMA.md`, `DESIGN.md`, `blocks/CONTRACT.md`.
